## ۱) دامنه — و ماندن بیرون از دامنه

**مکانیزم این تسک تحلیلِ LLM است، نه موتور قواعد.** موتور قواعد قطعی تسک ۱۱ (`services/medication_safety.py` + `/medications/check`) **نه صدا زده شد، نه تغییر کرد، نه گسترش یافت و نه تکرار شد** — فایل‌های جدید کاملاً مجزا (`ai_medication_safety.*`) هستند. بدون RxNorm/openFDA/Micromedex، بدون RAG/vector، بدون migration، بدون وابستگی جدید.

## ۲) معماری (بازاستفادهٔ کامل)

```
Use Case 1 (چت):  دکمهٔ «بررسی ایمنی دارو» در UI چت → medication_safety=true
                  → همان endpoint چت تسک ۱۰ → همان Context تسک ۹ + همان history
                  → فقط system prompt به پرامپت تخصصی ایمنی دارو عوض می‌شود
                  → پاسخ متنی با سکشن‌های برچسب‌دار (تداخل‌ها/نکات بیمار/اطلاعات ناقص/عدم‌قطعیت)

Use Case 2 (دیالوگ دارو): «بررسی ایمنی دارو» داخل دیالوگ افزودن دارو
                  → POST /patients/{id}/medications/ai-safety-check
                  → Context تسک ۹ (داروهای فعلی، آلرژی، شرایط، آزمایش، نوت‌ها/اسناد)
                  → ai.get_provider().complete() (همان Gemini تسک ۱۰/۱۰.۵ — بدون کلاینت جدید)
                  → parse/اعتبارسنجی JSON سمت سرور → قرارداد پاسخ ساخت‌یافته
```

- سرویس جدید `services/ai_medication_safety.py`: هستهٔ قواعد ایمنی مشترک (هرگز اطلاعات جعل نکن؛ تداخل احتمالی vs شناخته‌شده؛ عدم‌قطعیت صریح؛ اطلاعات ناقص را فهرست کن؛ بدون citation جعلی؛ فقط decision support) + دو پرامپت (JSON ساخت‌یافته / سکشن‌های متنی چت) + `parse_analysis` (حذف fence، یافتن JSON، اعتبارسنجی نوع‌ها)
- پیام کاربر با همان `ai.build_user_message` موجود ساخته می‌شود (همان سقف‌های ۲۰۰۰ کاراکتری) — کاندیدها + دوز + پرسش پزشک بالای Context

## ۳) قرارداد پاسخ (کوچک و عمدی)

`AiMedicationSafetyCheckResponse`: `overall_assessment` (فارسی) · `interactions[]` (هر مورد با پیشوند «تداخل احتمالی/شناخده‌شده») · `patient_factors[]` · `missing_information[]` · `uncertainty` (nullable) · `disclaimer` ثابت («این تحلیل توسط هوش مصنوعی ارائه شده و جایگزین قضاوت و تصمیم پزشک نیست.») · echo کاندیدها + `generated_at`. بدون enum شدت، بدون rule_id، بدون کد دارو — محتوا از مدل است.

درخواست: `medications` (۱ تا ۵ مورد؛ `name` + `dose` اختیاری) + `question` اختیاری — داروهای چندگانه پشتیبانی می‌شوند (ترکیب‌های مرتبط؛ موتورِ کل-regimen نیست).

## ۴) مدیریت خطا (تست‌شده)

| حالت | نتیجه |
|---|---|
| JSON مدل سالم (حتی داخل ```json fence) | 200 — فیلدهای اعتبارسنجی‌شده |
| خروجی ناساخت‌یافته (نثر بدون JSON / فیلد غایب / نوع اشتباه) | **502 فارسی — هرگز خروجی خام یا تحلیل جعلی** |
| شکست provider (شبکه/کلید) | 502 با لاگ علت واقعی؛ «جریان ثبت دارو دست‌نخورده است» |
| AI کانفیج نشده | 503 |
| Context ناقص/خالی بیمار | تحلیل انجام می‌شود؛ اطلاعات ناقص از مدل عبور داده می‌شود — دادهٔ غایب جعل نمی‌شود |
| بیمار ناشناخته / اعتبارسنجی | 404 / 422 |

## ۵) فرانت‌اند

- **دیالوگ افزودن دارو** (`medication-actions.tsx`): دکمهٔ «بررسی ایمنی دارو» (فعال وقتی نام دارو پر باشد) → حالت loading → پنل نتیجه: ارزیابی کلی + «تداخل‌ها» (کهربایی) + «نکات خاص این بیمار» + «اطلاعات ناقص» + عدم‌قطعیت ایتالیک + disclaimer. **ذخیره هرگز بلاک نمی‌شود** — CRUD دارو دست‌نخورده؛ خطای تحلیل فقط پیام قرمز + امکان تلاش مجدد.
- **چت** (`clinical-chat.tsx`): دکمهٔ toggle «بررسی ایمنی دارو» (affordance صریح — بدون keyword detection) → placeholder راهنما → همان حباب‌های گفتگو، همان history سمت کلاینت؛ پاسخ با سکشن‌های برچسب‌دار مدل رندر می‌شود.

## ۷) راستی‌آزمایی زنده (backend واقعی :8003، کلید واقعی Gemini)

```
1) context بیمار تست: meds=1, conditions=1, allergies=1 ✓
2) ai-safety-check (Warfarin 5mg + پرسش فارسی) → واقعاً به Gemini فرستاده شد
   لاگ: [ai-request] provider=gemini model=gemini-3.6-flash key_present=True
   پاسخ Google: 403 HTML در لبه (بلاک شبکهٔ شناخته‌شدهٔ این ماشین — بدون AI_PROXY)
   → نگاشت تمیز: 502 {"detail": "تحلیل ایمنی دارو انجام نشد… جریان ثبت دارو دست‌نخورده است."} ✓
3) chat با medication_safety=true → همان مسیر → 502 نگاشت‌شده ✓
4) ذخیرهٔ دارو بعد از شکست AI → 201 (medication id=7) — گردش کار سالم ✓
5) cleanup بیمار تست ✓
```

**صادقانه:** پاسخ موفق واقعی Gemini روی این ماشین قابل‌تست نیست (بلاک شبکه؛ همان محدودیت مستند تسک‌های ۱۲/۱۳). مسیر موفق با provider فرقی کامل تست شده (۱۷ تست) و مسیر خطای واقعی زنده راستی‌آزمایی شد. با `AI_PROXY` فعال، همان مسیر بدون تغییر کد جواب موفق می‌دهد.

## ۸) محدودیت‌ها

1. پاسخ موفق LLM روی این ماشین live نشد (بلاک شبکه) — با AI_PROXY فعال می‌شود.
