# گزارش تسک ۵ — فرانت‌اند (فهرست بیماران و پروندهٔ بالینی)

- **پروژه:** Clinical AI Copilot — دستیار هوشمند بالینی برای پزشکان
- **تسک:** تسک ۵ (Task 5) — فرانت‌اند فارسی RTL با مصرف APIهای واقعی تسک ۳ و ۴
- **تاریخ اجرا:** 2026-08-26
- **وضعیت:** ✅ تکمیل‌شده و راستی‌آزمایی‌شده (tsc + build + اجرای زنده SSR روی دادهٔ seed)
- **کامیت:** هنوز کامیت نشده است

---

## ۱) صفحات ساخته‌شده

| مسیر | نوع | توضیح |
| --- | --- | --- |
| `/` | Static | صفحهٔ فرود با دکمهٔ «ورود به فهرست بیماران» |
| `/patients` | Dynamic (SSR) | فهرست بیماران: جست‌وجو (نام/کد ملی)، صفحه‌بندی، دکمهٔ «بیمار جدید» (Dialog)، جدول shadcn |
| `/patients/[id]` | Dynamic (SSR) | پروندهٔ بالینی از `GET /overview`: پروفایل + مشکلات بالینی + حساسیت‌ها + داروهای فعال + ۵ آزمایش اخیر + ۵ یادداشت اخیر |
| `not-found` | Static | صفحهٔ ۴۰۴ فارسی |

## ۲) کامپوننت‌های ساخته‌شده

**بیمار:** `patient-form-dialog` (ایجاد/ویرایش پروفایل) · `patient-actions` (Add/Edit/Delete با تأیید حذف)
**بالینی:** `condition-actions` · `allergy-actions` · `medication-actions` (شامل دکمهٔ «قطع دارو» که تاریخچه را حذف نمی‌کند)
**مشترک:** `empty-state` · `error-state` (با «تلاش مجدد») · `confirm-dialog`
**shadcn جدید:** `dialog` · `input` · `label` · `select` · `textarea` · `table` · `skeleton` · `separator`

## ۳) یکپارچه‌سازی API (همه از `lib/api.ts` تایپ‌دار، بدون وابستگی خارجی)

`GET/POST /patients` · `PATCH/DELETE /patients/{id}` · `GET /patients/{id}/overview` · `POST/GET /patients/{id}/conditions` + `PATCH/DELETE /conditions/{id}` · همان الگو برای allergies و patient-medications · متن خطاهای فارسی بک‌اند (404/409) مستقیم نمایش داده می‌شود.

## ۴) معماری

- **Server Components برای دادهٔ اولیه** (SSR فارسی + قابل راستی‌آزمایی با curl) + **Client Components کوچک فقط برای تعامل** (فرم‌ها/حذف) که بعد از هر عملیات `router.refresh()` می‌کنند — الگوی استاندارد App Router، بدون state management اضافه.
- جست‌وجو/صفحه‌بندی با URL params (`?q=`, `?page=`) — حتی بدون JS کار می‌کند.
- `force-dynamic` + `cache: "no-store"` — داده همیشه تازه؛ build بدون بک‌اند هم موفق است.
- تاریخ‌ها با `Intl` + `fa-IR` (تقویم جلالی)؛ سن از تاریخ تولد محاسبه می‌شود.
- برچسب‌های enum فارسی در `lib/format.ts` (جنسیت، شدت حساسیت، وضعیت دارو، پرچم آزمایش، منبع یادداشت).

## ۵) نتایج تست/بیلد

| بررسی | نتیجه |
| --- | --- |
| `npx tsc --noEmit` | ✅ بدون خطا |
| `npm run build` | ✅ موفق — `/` و 404 استاتیک، `/patients` و `/patients/[id]` داینامیک |
| RTL | ✅ `<html lang="fa" dir="rtl">` + DirectionProvider + Vazirmatn |
| SSR با دادهٔ واقعی | ✅ `/patients` هر ۳ بیمار seed؛ `/patients/5` همهٔ بخش‌ها (دیابت/Metformin/پنی‌سیلین/HbA1c/یادداشت/۵۸ ساله) |
| جست‌وجو | ✅ `?q=مریم` فقط مریم احمدی |
| ۴۰۴ | ✅ `/patients/9999` → صفحهٔ فارسی |
| CORS مسیر مرورگر | ✅ preflight POST → 200 با `access-control-allow-origin: http://localhost:3000` |
| دادهٔ جعلی هاردکد | ✅ هیچ — اسکن src انجام شد؛ فقط placeholder های «مثال:» در فرم‌ها |

## ۶) هشدارها

1. **تست فرانت‌اند (Jest/Vitest/Playwright) هنوز تنظیم نشده** — چون هیچ تنظیمی موجود نبود؛ به‌عنوان فاز بعدی پیشنهاد می‌شود.
2. ورودی تاریخ میلادی (input type=date) است؛ انتخابگر تاریخ شمسی فاز بعدی است.
3. خطاهای 422 اعتبارسنجی پیام عمومی فارسی می‌گیرند (جزئیات فیلدبه‌فیلد پیاده نشد).
4. Docker Desktop بعد از ری‌استارت ماشین دوباره استارت شد (برای postgres).
5. id بیماران seed پس از reseed تسک ۴ از ۵ شروع می‌شود (رفتار طبیعی sequence) — مشکلی نیست.

## ۷) محدودیت‌های شناخته‌شده

- اسناد، یادداشت صوتی، تایم‌لاین، خلاصهٔ هوش مصنوعی و ارجاع شواهد در UI نیستند (فازهای بعدی — طبق اصل «بدون پیاده‌سازی پیش‌دستانه»).
- حذف بیمار همهٔ داده‌های مرتبط را پاک می‌کند — در دیالوگ تأیید به‌صورت برجسته هشدار داده شده است.
- فهرست بیماران انگلیسی/فارسی را با ILIKE جست‌وجو می‌کند (حساس به نوع حروف نیست ولی نیم‌فاصله باید دقیق باشد).

## ۸) گام بعدی
